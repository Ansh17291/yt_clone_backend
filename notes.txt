3. AsyncHandler.js :
this is a very useful file , basically it just helps us avoid writing try catch again and again (just see the down function in the asyncHandler.js file .. the try catch one). so what does it do it
suppose we have this like a route 
app.get("/users", async(req, res)=>{
    const users = await User.find();
    res.json(users);
})

here await User.find() is async fuc so it can throw error or time out therefore we wrap this in try and catch like this 

app.get("/users", async(req, res)=>{
    try{
        const users = await Users.find();

    }catch(err){
        res.json({
            error;
        })
        next(err) // pass to error handler. 

    }
})

writing this try catch is annoying again and again therefore we have this asyncHandler 

app.get("/users", asyncHandler(async(req, res)=>{
    const users = await User.find();
    res.json(users);
}))

here we not only handle the errors is they come but we reduce the number of line we write and make it cleaner , and ofc also avoid that try catch from being written again and again !.

in user.model.js we not only designed db but also hashed the password before storing it for that we use :

userSchema.pre("save", async function (next) {
    // the below if condition is written so that only when password is changed then only bcrypt is used otherwise while saving anything in  user.model would make password hash again and again, there hash if only when password is modified !
    if(this.isModified("password")){
        this.password = bcrypt.hash(this.password, 10);
        next(); // next ?? yeah yeah next beczz this is a middleware of mongoose 
    }
})

this is a middleware

we wrote a controller and a route for register .. just made the route no logic is written for now 

1. we made controller named registerUser which is covered inside asyncHandler function (remember asyncHandler is used for handling try catch and async requests either by using try catch or promises) , controller is where the logic is written . 

2. then we made a route , (user.routes.js) here we will just declare the routes not the logic 
    const router = Router 
    router.route("/register").post(registerUser)
    export default router;

3. then in the app.js file we will 
    import userRouter from user.routes.js
    app.use("/api/users", userRouter)

now i'll explain the whole process , so in app.js we have app.use("/api/users", userRouter) here userRouter comes from user.routes.js , its like saying all the routes that have the url of the type /api/users will be handled by the userRouter 
then in userRouter we declare the routes , like router.route("/register").post(registerUser), here registerUser is a controller that has the logic for handling the register of users , 
so the final url to send request becomes , "https://localhost:8000/api/users/register"

things to keep in mind , 
1. in app u define the declare the prefix for the route , 
    import userRouter from "./routes/user.routes.js"
    app.use("/api/users", userRouter)
    
2. In user.routes.js we declare the routes for only users 
    const router = Router();
    // https://localhost:8000/api/users/register
    router.route("/register").post(registerUser)

3. then in user.controller.js we write the logic for that particular route , like above /register is handled by the function registerUser which is written as a controller in usre.controller.js which has the logic for registeration
